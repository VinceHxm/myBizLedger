# myBizLedger 产品与工程规范

> 本文档约束公司账项目（`myBizLedger`）的产品定位、数据模型、记账规则、UI 与工程约定。  
> 后续改功能 / 写 Agent Skill / 做 UI 时，优先遵循本文。个人记账项目 `myBookkeeping` 只作为技术底座参考，**业务模型不沿用**。

---

## 1. 产品定位

- **家庭小公司内部业务账**：10–20 人左右的小公司 / 个体户，由老板或家人日常录入，请来的会计**每月核对一次**。
- **一句话**：家人只管「记一笔业务」，系统自动生成标准凭证；每月导出 Excel 核对包给会计，核对完成后结账锁定。
- **首要目标是准确**：防错靠系统机制（强制平衡、银行对账、发票核对、结账锁定、全程留痕），不靠人细心。
- **不做**：100 人以上的大公司、细分岗位流程（制单 / 审核 / 出纳 / 主管多级审批）、直接对接电子税务局申报、工资社保自动计算、进销存库存数量管理。
- **与会计的分工**：本系统是**内部账 + 凭证草稿**；正式税务账与纳税申报仍由会计完成。本系统负责让会计拿到的数据完整、可核对。

## 2. 主体类型与纳税人身份

两个维度相互独立，建账套时分别选择，之后可变更（变更从指定期间起生效）。

| 维度 | 取值 | 影响 |
|------|------|------|
| 主体类型 `entityType` | `company` 公司 / `individual` 个体工商户 | 所得税：公司算企业所得税；个体户算经营所得个税，无企业所得税 |
| 纳税人身份 `vatType` | `general` 一般纳税人 / `small` 小规模纳税人 | 增值税算法、发票抵扣、申报频率 |

### 2.1 三类主体对比（政策以当地税务局最新口径为准）

| | 个体工商户 | 小规模纳税人公司 | 一般纳税人公司 |
|---|---|---|---|
| 增值税 | 一般为小规模 | 销售额 × 征收率（多为 1%），**进项不抵扣** | 销项 − 进项，税率 13% / 9% / 6%，**进项可抵扣** |
| 增值税免征额 | 月 10 万以内免 | 月 10 万（季 30 万）以内免 | 无 |
| 增值税申报 | 多为按季 | 多为按季 | **按月** |
| 所得税 | 经营所得个税（5%–35%） | 企业所得税（小型微利实际约 5%） | 同左 |
| 建账要求 | 简易 | 规范复式账 | 复式账，发票管理最重 |

### 2.2 实现优先级

1. **一般纳税人公司**（当前实际使用，一期起支持）。
2. 小规模纳税人 / 个体户（三期）：计税规则可替换，底层凭证与科目共用，不另建模型。

> 个体户底层同样走复式凭证，只在界面上简化，避免日后转为公司时数据迁不过去。

## 3. 核心原则（必须遵守）

### 3.1 业务优先，凭证自动

- 录入人员只面对**业务单**（收货款、付货款、报销、发工资……），填价税合计、税率、往来单位、资金账户即可。
- **不含税金额、税额拆分与会计科目选择由业务模板完成**，生成凭证草稿。
- 老板 / 录入可以在凭证层手工调整分录（会计不能改，只读）；调整后凭证标记「已手改」，不再随业务单自动重算。

### 3.2 单一记账入口

- 延续 `myBookkeeping` 理念：**首页只有一个主 CTA「记一笔」**，进入后选业务类型。
- 发票录入、银行流水导入、手工凭证等放在各自二级页，不在首页并列记账按钮。

### 3.3 确认后不可删改，只能冲销

| 状态 | 可编辑 | 可删除 | 说明 |
|------|--------|--------|------|
| `draft` 草稿 | 是 | 是 | 业务单刚保存、凭证未确认 |
| `confirmed` 已确认 | 否（需先撤回到草稿，留日志） | 否 | 所在期间未结账时可撤回 |
| `checked` 会计已核对 | 否 | 否 | 会计标注通过 |
| `reversed` 已冲销 | 否 | 否 | 生成一张红字冲销凭证抵消 |

- **期间结账后**：该期间所有单据只读；错误只能在当前开启的期间做冲销或调整凭证。
- 任何状态下都**不物理删除**已确认数据。

### 3.4 金额与税额

- 金额全程用**分（int64）**存储，展示时转元；禁止浮点运算。
- 税额默认 = 四舍五入(价税合计 ÷ (1 + 税率) × 税率)，不含税金额 = 价税合计 − 税额。
- **有发票时以发票票面税额为准**；手改税额与计算值相差超过 1 元时给出提示（不阻止保存）。

### 3.5 数据隔离

- 所有业务数据按 `companyId`（账套）隔离；每个查询必须带账套条件。
- 一个用户可加入多个账套，在顶栏切换当前账套。
- 需有隔离测试：A 账套成员无法读写 B 账套任何数据。

## 4. 角色

| 角色 | 能力 |
|------|------|
| `owner` 老板 | 全部权限：账套设置、成员管理、结账、反结账 |
| `bookkeeper` 录入 | 记业务、录发票、导入银行流水、确认凭证；不能结账 / 反结账 |
| `accountant` 会计 | **只读**全部数据；导出 Excel；在凭证上标注「已核对 / 有问题」。不能新增 / 修改 / 删除业务单、凭证、发票，不能结账 |

- 会计的「核对标注」只写 `ReviewNote`，不改动任何账务数据。
- 不做多级审批流。
- 账套必须至少保留一个 `owner`。
- 平台级管理员（用户注册、停用）沿用 `myBookkeeping` 的 `user / admin` 机制，与账套内角色分开。

## 5. 信息架构

```
首页 /
  ├─ 本月概览：收入 / 支出（不含税）/ 本月增值税估算 / 资金余额合计
  ├─ 待办：未匹配银行流水 N 条、待勾选进项发票 N 张、会计标注问题 N 条、草稿 N 张
  └─ 大按钮「记一笔」→ /biz/new（先选业务类型）

底栏 / 侧栏：首页 | 业务 | 凭证 | 发票 | 核对 | 我的

业务     /biz          业务单列表（按期间、类型、往来单位、状态筛选）
凭证     /vouchers     凭证列表、凭证详情（分录 + 核对标注 + 操作日志）
发票     /invoices     销项 / 进项发票台账，抵扣勾选状态
核对     /review       月度核对工作台：银行对账、发票与款项核对、增值税测算、导出、结账
我的     /mine         账套设置、成员、科目、往来单位、资金账户、业务模板、个人设置
```

## 6. 核心数据模型

| 模型 | 作用 | 关键字段 |
|------|------|----------|
| `Company` 账套 | 一个公司 / 个体户一套账 | 名称、税号、`entityType`、`vatType`、启用年月、附加税税率配置、必传附件阈值（默认 200 元） |
| `Member` 成员 | 用户在账套中的角色 | `companyId`、`userId`、`role` |
| `Subject` 会计科目 | 按《小企业会计准则》预置，可加明细 | 编码、名称、类别（资产 / 负债 / 权益 / 成本 / 损益）、余额方向、上级、是否末级、是否按往来单位核算、是否停用 |
| `Partner` 往来单位 | 客户 / 供应商 / 员工 / 股东 | 名称、类型、税号、开户行与账号、备注 |
| `FundAccount` 资金账户 | 银行 / 现金 / 微信 / 支付宝 | 名称、类型、对应科目（`Subject` 末级）、期初余额、账号后四位 |
| `BizTemplate` 业务模板 | 某类业务生成什么分录 | 业务类型、分录规则（见 §7）、是否系统预置 |
| `BizEntry` 业务单 | 「记一笔」 | 期间、业务日期、类型、价税合计、税率、不含税金额、税额、往来单位、资金账户、费用/收入科目、摘要、附件、关联发票、关联凭证、状态 |
| `Voucher` 凭证 | 自动生成或手工 | 期间、凭证字号（按期间连续编号）、日期、摘要、来源（业务单 / 手工 / 冲销 / 系统结转）、状态、是否已手改 |
| `VoucherLine` 分录 | 凭证明细行 | 科目、借方金额、贷方金额（二选一）、往来单位、摘要 |
| `Invoice` 发票 | 销项 / 进项台账 | 方向、类型（专票 / 普票 / 数电专 / 数电普）、发票号码、开票日期、往来单位、金额、税额、税率、价税合计、抵扣状态（未勾选 / 已勾选 / 不可抵扣 / 已转出）、抵扣所属期、关联业务单、附件 |
| `Period` 会计期间 | 按月 | 年月、状态（`open` / `closed`）、结账人、结账时间 |
| `BankStatementLine` 银行流水 | 网银导出导入 | 资金账户、交易时间、收支方向、金额、对方户名、摘要、流水号、匹配状态、关联业务单 |
| `ReviewNote` 核对标注 | 会计对凭证的意见 | 凭证、结论（已核对 / 有问题）、说明、处理状态 |
| `Attachment` 附件 | 原始凭证照片 / PDF | 关联对象类型与 ID、MinIO 路径（沿用 `myBookkeeping` 实现） |
| `AuditLog` 操作日志 | 所有增删改 | 操作人、对象、动作、修改前 JSON、修改后 JSON、时间 |

## 7. 业务类型与分录模板（一般纳税人）

记号：价税合计 = A，不含税 = N，税额 = T（A = N + T）。

| 业务类型 | 借方 | 贷方 |
|----------|------|------|
| 销售开票并收款 | 资金账户 A | 主营业务收入 N；应交增值税（销项税额）T |
| 销售开票未收款 | 应收账款（客户）A | 主营业务收入 N；应交增值税（销项税额）T |
| 收回货款 | 资金账户 A | 应收账款（客户）A |
| 预收货款 | 资金账户 A | 预收账款（客户）A |
| 采购收专票（付款 / 赊购） | 库存商品 / 原材料 / 费用科目 N；待认证进项税额 T | 资金账户 / 应付账款（供应商）A |
| 采购收普票或无票 | 库存商品 / 原材料 / 费用科目 A | 资金账户 / 应付账款（供应商）A |
| 支付货款 | 应付账款（供应商）A | 资金账户 A |
| 费用报销 | 管理费用 / 销售费用 - 明细 N（专票时另借待认证进项税额 T，否则全额 A） | 资金账户 / 其他应付款（员工）A |
| 计提工资 | 管理费用 / 销售费用 - 工资 | 应付职工薪酬 |
| 发放工资 | 应付职工薪酬 | 资金账户；应交个人所得税；其他应付款 - 社保个人部分 |
| 缴纳税费 | 应交税费 - 对应明细 | 资金账户 |
| 资金互转 | 转入资金账户 | 转出资金账户 |
| 股东投入 / 借入 | 资金账户 | 实收资本 / 其他应付款（股东） |
| 银行手续费 / 利息 | 财务费用（利息收入为贷方负数或贷财务费用） | 资金账户 |

**系统动作生成的凭证**：

| 动作 | 分录 |
|------|------|
| 进项发票勾选确认 | 借 应交增值税（进项税额）T / 贷 待认证进项税额 T |
| 月末转出未交增值税（二期后） | 借 应交增值税（转出未交增值税）/ 贷 未交增值税 |
| 计提附加税（二期后） | 借 税金及附加 / 贷 应交城建税、教育费附加、地方教育附加 |
| 冲销 | 原凭证分录金额取负，摘要前缀「冲销：」并关联原凭证 |

- 模板可在「我的 → 业务模板」调整默认科目（如费用明细），系统预置模板不可删除。
- 业务单所选费用 / 收入科目必须是末级科目。

## 8. 防错机制

| # | 机制 | 规则 |
|---|------|------|
| 1 | 借贷平衡 | 凭证借方合计 ≠ 贷方合计时不能确认；每行借贷只能填一边且不为 0 |
| 2 | 银行对账 | 导入网银流水后按「金额 + 日期 ±3 天 + 对方户名」自动匹配业务单；月末系统余额与银行余额不一致标红，并列出未匹配项 |
| 3 | 发票与款项核对 | 列出「有发票无收付款」「有收付款无发票」「进项专票未勾选」清单 |
| 4 | 结账锁定 | 结账前检查：无草稿、银行已对平、会计标注的问题均已处理；结账后期间只读 |
| 5 | 全程留痕 | 业务单、凭证、发票、科目、期间状态的任何变更写 `AuditLog` |
| 6 | 附件要求 | 支出超过账套阈值（默认 200 元）必须上传附件才能确认；低于阈值可选上传，不强制 |
| 7 | 重复检测 | 同一发票号码不可重复录入；同日、同往来单位、同金额的业务单保存时提示可能重复 |
| 8 | 期间校验 | 业务日期必须落在开启的期间内；不能跨期间修改 |

## 9. 月度核对流程

```
日常记业务
  → 导入当月银行流水，完成自动 / 手工匹配
  → 补齐发票，更新进项勾选状态（与电子税务局勾选结果一致）
  → 系统测算本月增值税：销项合计 − 本期已勾选进项 + 进项转出 − 上期留抵
  → 导出 Excel 核对包发给会计
  → 会计逐条标注「已核对 / 有问题」
  → 修正问题（冲销或调整凭证）
  → 结账锁定
```

### 9.1 Excel 核对包

一个 `.xlsx` 文件，文件名 `账套名_YYYY-MM_核对包.xlsx`，包含工作表：

| 工作表 | 内容 |
|--------|------|
| 序时账 | 凭证字号、日期、摘要、科目编码、科目名称、往来单位、借方、贷方 |
| 科目余额表 | 科目、期初余额、本期借方、本期贷方、期末余额 |
| 银行对账 | 每个资金账户：系统余额、银行余额、差额、未匹配流水明细 |
| 销项发票 | 发票号码、日期、客户、金额、税额、价税合计、关联业务单 |
| 进项发票 | 发票号码、日期、供应商、金额、税额、抵扣状态、抵扣所属期 |
| 增值税测算 | 销项、进项、转出、上期留抵、本期应纳 / 留抵，附加税估算 |
| 往来余额 | 客户应收、供应商应付、员工 / 股东其他应收应付余额 |

- **列顺序以会计现用 Excel 模板为准**：拿到会计模板后在此表登记对应列，导出代码按此实现。
- 会计在 Excel 中发现问题后，也可直接在系统凭证详情里标注（推荐），避免两边信息不一致。

## 10. 分期计划

| 阶段 | 范围 | 验收标准 |
|------|------|----------|
| 一期：能用 | 账套 / 成员 / 角色、预置科目、往来单位、资金账户、业务模板、记一笔业务、自动凭证、手工凭证、发票台账、期间结账锁定、Excel 核对包导出 | 一个月的真实业务全部录入后，导出的科目余额表与会计手工账一致 |
| 二期：防错 | 银行流水导入与自动匹配、发票与款项核对清单、操作日志查看、会计在线标注、结账前检查、冲销凭证、月末增值税与附加税凭证 | 结账前检查能拦住未对平、未处理问题 |
| 三期：省事 | AI 识别发票生成业务单、资产负债表 / 利润表、小规模纳税人与个体户计税规则、常用业务快捷模板 | 识别结果须经确认页确认后才落库 |

## 11. UI 设计规范

- **视觉语言沿用 `myBookkeeping`**（松绿主色、`Noto Sans SC` + `Outfit`、半透明卡片、light / dark / system 主题），但**桌面优先**：凭证、台账、核对页以宽表格为主；移动端保证记一笔、拍附件、查看待办可用。
- 金额列右对齐、等宽数字、千分位；借方 / 贷方分列，不用正负号混排。
- 已结账期间的数据页顶部显示「已结账，只读」横幅。
- 记一笔页：先选业务类型（大图标网格）→ 表单只展示该类型需要的字段 → 底部实时预览将生成的分录。
- 多笔 / 重确认流程（银行流水匹配、AI 识别结果、结账检查）用**独立子页**，不用 Dialog。
- 表单防遮挡规则同 `myBookkeeping` §4.3.1：密集表单 `hide-details` + 独立说明文案，禁止连续 outlined 字段叠用 `persistent-hint`。

### 12.1 从 myBookkeeping 复用

| 可复用 | 说明 |
|--------|------|
| 登录 / 注册 / Redis 会话 / 平台管理员 | 直接复制后去掉个人记账相关初始化 |
| 附件上传与 MinIO 存储、缩略图预览 | 关联对象改为通用的「类型 + ID」 |
| DeepSeek 识图调用封装 | Prompt 改为发票识别 |
| 前端主题、`MetaHead`、`EntityCard`、`DeleteConfirmDialog`、`AttachmentUpload`、`useBreakpoint`、`money.ts` | 原样复制后按需调整 |
| handler / service / model 分层、`xxxBody` + `toInput()` 约定 | 同 `myBookkeeping` §5.1 |

**不复用**：`Transaction` / `Account` / `Category` 模型、信用卡账单、计费规则、团购券、理财校准等个人记账业务。

### 12.2 后端约定

- `cmd/server` → `handler` → `service` → `model` + `database`。
- 中间件从会话解析用户与当前账套，注入 `companyId` 与 `role`；service 层所有方法第一个业务参数为 `companyId`。
- 凭证生成、冲销、结账在**数据库事务**内完成；凭证字号在事务内按期间加锁递增。
- 数据库变更依赖 GORM AutoMigrate；部署后需手动重启后端。
